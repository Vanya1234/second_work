# SQL Injection и Reflected XSS

Лабораторная работа по безопасности веб-приложений на Python.

В этой работе я сделал небольшой сайт с двумя уязвимостями: SQL Injection в поиске студентов и Reflected XSS в форме приветствия. Для проверки написал отдельный Python-скрипт, а исправления сохранил во второй версии приложения и в файле `patch.diff`.

Использовал только стандартную библиотеку Python: `wsgiref`, `sqlite3`, `urllib`, `html` и `argparse`. Сервер запускается на `127.0.0.1:8000`. Все записи в базе вымышленные.

## Файлы проекта

```text
python-security-lab/
├── app_vulnerable.py   # версия с уязвимостями
├── app_fixed.py        # исправленная версия
├── exploit.py          # проверка обычных запросов и атак
├── patch.diff          # изменения для исправления
├── README.md
└── .gitignore
```

## Запуск

Нужен Python 3.10 или новее. Дополнительные пакеты не требуются. Команды выполняются из папки проекта.

Уязвимая версия:

```bash
python3 app_vulnerable.py
```

После запуска сайт доступен по адресу [http://127.0.0.1:8000](http://127.0.0.1:8000).

На главной странице две формы:

- поиск студента по имени: `alice`, `bob` или `carol`;
- приветствие с введённым текстом.

Например, поиск `alice` возвращает одну запись `alice — DEMO-101`, а приветствие `Мир` выводит `Привет, Мир!`.

База SQLite создаётся в памяти при каждом поиске и содержит три записи. После обработки запроса она закрывается, поэтому отдельного файла базы нет.

## Проверка уязвимостей

Пока сервер работает, в другом терминале:

```bash
python3 exploit.py
```

Скрипт отправляет пять GET-запросов: обычный поиск, обычное приветствие, поиск отсутствующего имени, SQL Injection и XSS. Для каждого запроса выводит URL, HTTP-статус и HTML-ответ.

### SQL Injection

В уязвимой версии имя напрямую подставляется в запрос:

```python
query = f"SELECT name, group_name FROM students WHERE name = '{name}'"
```

Вместо имени передаётся строка:

```text
' OR '1'='1
```

Получается такой SQL:

```sql
SELECT name, group_name FROM students WHERE name = '' OR '1'='1'
```

Условие `'1'='1'` всегда истинно, поэтому запрос возвращает всех трёх студентов. Так обходится условие поиска. Скрипт сравнивает этот результат с поиском имени `nobody`, для которого записей нет.

Ту же строку можно ввести в форму поиска на сайте.

### Reflected XSS

В форму приветствия передаётся:

```html
<script>alert('XSS')</script>
```

Приложение вставляет этот текст в HTML без экранирования. При открытии страницы браузер выполняет `alert` и показывает окно с текстом `XSS`.

Python-скрипт проверяет наличие неэкранированного тега в ответе. Сам JavaScript он не выполняет. Для проверки выполнения нужно открыть напечатанный URL в браузере или отправить эту строку через форму приветствия.

XSS здесь отражённый: текст берётся из текущего запроса и сразу попадает в ответ, без сохранения в базе.

## Исправления

### SQL Injection

Я заменил подстановку имени на параметризованный запрос:

```python
query = "SELECT name, group_name FROM students WHERE name = ?"
return database.execute(query, (name,)).fetchall()
```

SQL-команда и значение имени передаются отдельно. Строка атаки теперь воспринимается как одно имя и не меняет условие запроса. Совпадений с таким именем в базе нет.

### XSS

Перед выводом текста я добавил `html.escape`:

```python
body = f"<p>Привет, {escape(text)}!</p>"
```

Специальные символы HTML экранируются, и браузер показывает введённый текст вместо выполнения тега. В данном случае значение выводится в текст внутри `<p>`.

## Проверка исправленной версии

Сначала остановить уязвимую версию через `Ctrl+C`, затем запустить:

```bash
python3 app_fixed.py
```

В другом терминале выполнить те же запросы, указав ожидаемую версию:

```bash
python3 exploit.py --expect fixed
```

Параметр `--expect` меняет только ожидаемые результаты проверки. Сами запросы остаются прежними.

| Запрос | До исправления | После исправления |
| --- | --- | --- |
| Поиск `alice` | Одна запись | Одна запись |
| Поиск `nobody` | Нет записей | Нет записей |
| SQL Injection | Три записи | Нет записей |
| Приветствие `Мир` | Обычный текст | Обычный текст |
| XSS в браузере | Окно `XSS` | Текст `<script>alert('XSS')</script>` |

При правильном результате скрипт выводит `Проверки пройдены.` и завершается с кодом `0`. При несовпадении результатов или ошибке соединения — с кодом `1`.

Работа была проверена на macOS с Python 3.14.8. Выполнение XSS дополнительно проверялось в Chrome.

## Применение патча

Посмотреть изменения:

```bash
cat patch.diff
```

Применить патч к копии уязвимого файла:

```bash
cp app_vulnerable.py app_patched.py
patch app_patched.py < patch.diff
```

Сравнить результат с исправленной версией:

```bash
diff -u app_fixed.py app_patched.py
```

Если вывода нет, файлы совпадают. Получившийся `app_patched.py` можно запустить вместо `app_fixed.py` и проверить командой `python3 exploit.py --expect fixed`.
